# code-to-api-doc

给 agent 一个代码地址，产出两类**能直接交给别人**的文档：接口速览卡（Markdown）和技术设计说明书（HTML）。

不是"把代码注释汇总成 API 列表"。这个技能的核心约束是**每条结论都要有出处**：代码里读到的标【事实】，推断的标【假设】，读不到的标【待确认】并生成缺口编号。宁可留空，不许按 REST 常识补。

- 当前版本：**1.3.1**
- 配套标准：接口速览卡 V2、技术设计说明书 V2.3+
- 变更历史：[CHANGELOG.md](CHANGELOG.md)

## 两个交付物

| 交付物 | 给谁看 | 形态 |
| --- | --- | --- |
| 接口速览卡 | 需要快速搞懂**单个**接口的人：谁在调、什么时候会炸 | `survey-cards/*.md`，一接口一卡，固定 8 区块 |
| 技术设计说明书 | 没参与需求讨论、要照着实施的协作者 | 一个扁平目录 + 主 HTML，13 章 + 附录 + 自检 |

两份标准不是并列关系。速览卡先把业务语义逼出来，说明书的第 6 章直接复用卡片结论，不写两套互相矛盾的口径。

## 安装

把整个目录放到你的技能目录下，两种常见位置任选：

```bash
# Claude Code / 通用 .agents 约定
git clone https://github.com/veternal/code-to-api-doc.git ~/.agents/skills/code-to-api-doc

# WorkBuddy 用户级技能
git clone https://github.com/veternal/code-to-api-doc.git ~/.workbuddy/skills/code-to-api-doc
```

技能列表在会话启动时加载，**装完请新开一个对话**。如果新会话没识别到，用兜底指令：

```
读取 <技能目录>/SKILL.md 并按其中的流程执行，代码地址 E:/work/xxx
```

依赖：Node.js（用于扫描与机检脚本，需支持 `node --test`）。没有 Node 也能用，但只能走人工定位，且不能声称脚本已验证。

## 触发

最小可用版，一句话：

```
用 code-to-api-doc 技能，代码地址 E:/work/aigc-powerise-api，生成接口速览卡和技术设计说明书
```

推荐版，多给三个参数，产出质量差别明显：

```
用 code-to-api-doc 技能做接口文档。

代码地址：E:/work/aigc-powerise-api
范围：只做 controller 层里 /api/v1/program 相关的接口
输出目录：E:/work/docs
项目情况：Spring Boot 3 + Vue3 前后端分离，部署在 K8s，网关有统一前缀改写。
```

| 参数 | 为什么值得给 |
| --- | --- |
| 代码地址 | 不给就用当前工作目录，并在文档来源基线里写明"未指定" |
| 范围 | 接口超过 30 个会退化成"目录 + 少量卡片"，限定模块或路径前缀效果最好 |
| 输出目录 | 不给就落在当前工作目录，容易和代码混在一起 |
| 项目形态 | 单体 / 前后端分离决定第 5、7 章分组方式；网关前缀改写会影响路径拼接核对 |

分场景：

```
# 只要卡片
用 code-to-api-doc 技能，代码地址 E:/work/xxx，只出接口速览卡

# 只要说明书
用 code-to-api-doc 技能，代码地址 E:/work/xxx，生成说明书 HTML，这次不用写卡片

# 增量更新（保留旧编号与变更记录）
用 code-to-api-doc 技能更新文档。代码地址 E:/work/xxx，上一版在 E:/work/docs/xxx-devplan-20261101/
只补新增的 3 个接口和本次改动的页面，G/D 编号不要重排
```

## 产物结构

```
{项目代号}-devplan-{YYYYMMDD}/          # 扁平目录，不建子目录
├── {项目代号}-devplan-{日期}.html      # 主 HTML，唯一阅读入口
├── preview-PAGE01-default-desktop.html # 每个受影响页面 × 每个状态一份
├── diagram-FIG01.svg                   # 可选，图表离线备份
└── table-TASKS.csv                     # 可选，大表导出

survey-cards/                           # 速览卡独立存放，一接口一卡
└── GET-program-detail.md
```

说明书的全部生成文件直接写进交付目录，**不建子目录**；速览卡单独放 `survey-cards/`，只有作为说明书附件时才复制进去。接口多于 30 个时先出一页四列目录（接口标识、一句话用途、谁在调、失败影响），再按优先级逐张写卡。

HTML 数量 **不是固定的**，`1 个主 HTML + Σ(每个受影响页面 × 展示状态数)`：

| 场景 | 主 HTML | 预览 | 合计 |
| --- | --- | --- | --- |
| 纯后端，无前端页面 | 1 | 0 | 1 |
| 3 页 × 1 个状态 | 1 | 3 | 4 |
| 3 页，其中 1 页要正常+错误两态 | 1 | 4 | 5 |

## 速览卡 8 区块

阅读顺序固定：先业务后技术、先链路后字段、先正常后异常。卡头卡尾不计入。

| # | 区块 | 回答什么 |
| --- | --- | --- |
| 1 | 电梯摘要 | 干什么、谁在用、什么时候出问题（固定 3 行） |
| 2 | 它到底干什么 | 业务语言解释用途与"成功"的含义（避开禁词表） |
| 3 | 什么时候用 / 别用 | 适用场景、前置条件、替代方式、误用风险 |
| 4 | 上下游链路 | 谁调我、我调谁、等谁，各自超时与失败影响 |
| 5 | 一次调用发生什么 | 处理顺序、事务边界、同步返回点、异步分叉点 |
| 6 | 关键字段速查 | 最多 8 个，不设下限；标位置、约束、错用后果 |
| 7 | 状态与数据变化 | 改了谁、成功走到哪一步、有无其他副作用 |
| 8 | 失败地图 + 3 个坑 + Q&A | 出事怎么处理，怎么回答同事 |

第 2 块有封闭禁词表（`接口、字段、参数、实体、枚举、JWT、OpenAPI、HTTP、MQ、幂等、事务、ID、生产调度`），目的是强制用业务语言，而不是把术语换个说法。

| 章 | 内容 |
| --- | --- |
| 1 | 范围与总览 |
| 2 | 架构图 |
| 3 | 时序图（`alt` / `opt` 写可判定表达式） |
| 4 | 流程图（分支条件 R1—R4，11 列分支表） |
| 5 | 改动文件清单 |
| 6 | 接口详细案例（复用速览卡定位结论） |
| 7 | 前后端分工与**任务拆解**（不出排期） |
| 8 | 用户决策与信息缺口（D/G 编号一一映射） |
| 9 | 新增配置与数据库变更（含分支反向引用） |
| 10 | 风险、测试与发布 |
| 11 | 前端改动页面预览效果（1920×1080 等比缩放） |
| 12 | 问题排查（六类必查，只记真实报错） |
| 13 | Vibe Coding 经验总结（技术经验 + AI 协作经验） |

自检 Q01—Q20，状态只取「通过／不通过／未验证／不适用」，没实际跑浏览器的一律标未验证。

## 三条最容易被违反的约束

**1. 不编造。** 第 12 章只收真实发生过的报错——原始报错没留存就写"未留存，以下为复述"；六个类别（安装失败、版本冲突、网络、权限、API、部署）可以全是"否"，但"否"要给依据。第 13 章的"失败方案"必须有就用、没有就说明为什么没有，不许编一条凑数。

**2. 不写排期。** 都 vibe coding 了，第 7 章只做分工与任务拆解，不出工期、人天、里程碑、迭代计划、人员分配。第 10 章的"责任人"只记风险跟进人，不构成任务分配。

**3. 分支条件要可判定。** 菱形标签不许写"参数校验通过""权限满足"这类结论，要写 `order.amount > 0 且 items 非空`。用到配置或数据时带锚点：`CFG:9.1/gen.enabled`、`DB:9.2/program.status`，且 key 与表名必须和第 9 章逐字一致、能双向跳转。未配置、无记录、NULL 都要有明确走向。

## 脚本

```bash
# 扫描接口与前端页面，产出 endpoints.json / endpoints.md
node scripts/scan-endpoints.mjs <codeRoot> --out <输出父目录>

# 卡片结构机检（8 区块、三态标注、禁词、坑与问答数量）
node scripts/check-card.mjs <卡片路径>

# 版本一致性（frontmatter / 正文 / CHANGELOG 首条及日期）
node scripts/check-version.mjs [skillRoot]
```

扫描覆盖 Spring、NestJS、Express/Koa、FastAPI/Flask、Go 的常见静态路由写法，以及 OpenAPI/Swagger 的 YAML 路径块。

**它是轻量文本扫描，不是语法解析**，只产出候选。动态路径、别名继承、全局前缀、Express 挂载前缀、JSON 格式 OpenAPI 都会漏；匿名或识别不出处理函数的留空（摘要显示 `—`），不按相邻接口猜名字。候选不等于事实，写进卡片前必须回代码确认。

node scripts/check-version.mjs .

这些用例只证明样例行为，**不证明任意项目被完整扫描、接口实际可用、浏览器显示已验证**。修改脚本后必须重跑。

## 已知边界

- **第 11 章预览依赖前端路由能被扫到。** 约定式路由（Next / Nuxt 文件路由）扫不出 `path:`，需要按文件路径人工补 PAGE-ID 并登记缺口，不会假装全覆盖。
- **受影响页面全集 = 已提供预览的页面全集**，缺一个就得登记"待交付 + G-ID"，不能用"挑代表性页面"顶替。
- **旧文档不会自动升级。** 升级技能后，旧交付需按 CHANGELOG 的"对已交付文档的影响"增量补齐，不许只改文档版本号就声称通过。
- **未指定的默认值不是项目事实。** 桌面视口、浏览器、简体中文都是生成默认值，目标环境未给出时写"未指定，兼容性待验证"。
